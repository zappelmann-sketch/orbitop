# orbitop 0.3.0: Bau (Plan 2) – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** orbitop 0.3.0 bekommt drei Dinge:
- einen Schalter „Messzähler freigeben“ mit Admin-Passwort;
- einen Knopf „Installieren“ für die Intel-Werkzeuge;
- ausblendbare Hinweise.

Pakete, Auslöser und Matrix tragen das sicher in allen vier Formaten.

**Architecture:**
- **Helfer:** Ein eigener root-Helfer `counterhelper` kennt nur `on`, `off` und `sync`. Er setzt die Fähigkeit an `/usr/bin/intel_gpu_top` und die Leserechte der RAPL-Zähler.
- **Merkdatei:** `/etc/orbitop/counters-released` ist die Regel für den ganzen Rechner.
- **Auslöser:** Paket-Auslöser rufen `sync`, und eine feste udev-Regel wirkt beim Start.
- **App:** Sie liest den Zustand ohne root. Den Helfer ruft sie nur über das echte polkit-pkexec auf, durch ein Tor mit wachsender Sperre.
- **Knopf:** Er spricht PackageKit über den System-D-Bus an (Gio), mit festen Paketnamen.

**Tech Stack:**
- Python ≥ 3.12, nur Standardbibliothek und PyGObject/Gio.
- Oberfläche: GTK 4, WebKitGTK 6.0, Vanilla-JS als ES-Module.
- Tests: pytest, kopfloser Chrome, Bash und shellcheck.
- Pakete: Docker, debhelper, rpmbuild, makepkg.
- System: polkit, udev, PackageKit.

**Spec:** `docs/superpowers/specs/2026-11-19-orbitop-umbau-und-0.3.0-design.md`, Teil C, für den Abschluss auch Teil D.
- **Verbindlich für jede Bauweise ist das Security-Dokument** `docs/superpowers/specs/2026-11-19-orbitop-0.3.0-security-runde.md`.
- Daraus gelten die Abschnitte B2.1–B2.9 („Empfehlung“ und „Pflicht-Tests“) und Abschnitt 4 mit den Entscheidungen E1–E7.
- Nennt dieser Plan eine Einzelheit nicht, gilt das Dokument wörtlich.
- Jede Task nennt die Abschnitte, die sie umsetzt. Der Implementer liest sie vollständig.

### Q2: Nachrichtenvertrag

```text
init           + "counters": COUNTERS, "hidden_hints": [str], "install": {"usable": bool, "command": str}
COUNTERS       = {"marker": "on"|"off"|"unclear",
                  "usable": "yes"|"nohelper"|"nopkexec",
                  "manual_rule": bool,
                  "parts": [{"part": "perfmon"|"rapl",
                             "state": "works"|"missing"|"broken"|"manual"|"none"}]}
counters_state   {"type": "counters_state", "counters": COUNTERS,
                  "result": "ok"|"cancelled"|"denied"|"busy"|"locked"|"nohelper"|"error"|"unsafe"|"partial"}
install_state    {"type": "install_state",
                  "result": "installed"|"denied"|"failed"|"unavailable"|"busy"|"locked"|"closed"}
hints_state      {"type": "hints_state", "hidden_hints": [str]}
Seite → Python   {"type": "counters", "on": bool}
                 {"type": "install_tool"}
                 {"type": "hide_hint", "key": str}
                 {"type": "show_hints"}
```

- Exit-Codes des Helfers (Entscheidung Controller, Task 7 Fix 1): 0 → `ok`, 1 und 2 → `error`, 3 → `unsafe`,
  4 → `partial`; 126 → `cancelled`, 127 → `denied`. Nur `ok` nach pkexec setzt die Sperre zurück, nur 126/127 zählen
  als Ablehnung.
- `marker` und `parts` folgen der Tabelle in B2.5:
  - `none` heißt „aus, keine Wirkung“;
  - `unclear` heißt „aus, Zustand unklar“ (B2.2).
- `perfmon` steht nur auf Rechnern mit Intel-Grafik in `parts`. `rapl` steht immer darin, ohne Zonen mit `missing`.
- `manual_rule` ist `os.path.lexists("/etc/udev/rules.d/70-orbitop-rapl.rules")` (B2.9).
- `hide_hint.key` muss einer der Schlüssel der Fußzeile sein, sonst `None`:
  - `hint.igt_failed`
  - `hint.igt_missing`
  - `hint.igt_noperm`
  - `hint.nvsmi_missing`
  - `hint.rapl_noperm`
