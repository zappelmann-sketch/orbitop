# orbitop 0.2.0: Pakete, Paketquellen und Update-Kanal – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** orbitop 0.2.0 ist als `.deb`, als RPM für Fedora und openSUSE und als Arch-Paket aus signierten Paketquellen auf GitHub Pages installierbar. Neue Versionen kommen über das normale System-Update. Dazu kommen ein Autostart-Schalter je Benutzer und der Kill-Helfer mit eigener polkit-Action.

**Architecture:**
- Ein gemeinsames Skript legt den Dateibaum des Pakets an. Debian (debhelper), RPM (eine spec-Datei mit `%if 0%{?suse_version}`) und Arch (PKGBUILD) bauen daraus in Wegwerf-Containern.
- Quelle und Schlüssel stecken in eigenen kleinen Paketen (`orbitop-apt-source`, `orbitop-release`), damit `apt remove orbitop` keine verwaiste Quelle hinterlässt.
- Ein Site-Skript signiert Pakete und Metadaten mit dem lokalen Schlüssel und legt den Baum für den Zweig `gh-pages` an. Die Container-Matrix führt die README-Befehle gegen diesen Baum aus, und das Release-Skript verbindet alle Schritte.

**Tech Stack:** Python ≥ 3.12 (Standardbibliothek plus PyGObject), GTK 4, WebKitGTK 6.0, Vanilla-JS, pytest, kopfloser Chrome, Bash, shellcheck, Docker, debhelper, rpmbuild/rpmsign, createrepo_c, makepkg/repo-add, apt-ftparchive, GnuPG 2.4, lintian, rpmlint, namcap, `gh`.

**Spec:** `docs/superpowers/specs/2026-11-18-orbitop-stufe-2-pakete-update-kanal-design.md` (maßgeblich, nur der Teil 0.2.0). Sie baut auf den Specs vom 2026-11-16 und 2026-11-17 auf, deren Regeln weiter gelten.

## Review Focus

1. **`apt remove orbitop`, danach `apt update`:** Es darf kein Fehler und keine Warnung kommen. Ein Purge beider Pakete lässt keine Datei aus deren Dateilisten zurück. Test: Matrix-Schritt `remove` in Task 6.
2. **Seltsamer Inhalt im Autostart-Ordner:** ein Symlink nach anderswo, eine FIFO, eine Datei über 64 KiB, eine unlesbare Datei, ein relatives `XDG_CONFIG_HOME`, ein Systemeintrag unter `/etc/xdg/autostart`. Erwartet: kein Hängen, kein Schreiben außerhalb des eigenen Autostart-Ordners, ein richtiger Zustand. Tests in Task 2.
3. **Start aus einem Checkout ohne installiertes Paket:** Der Autostart-Schalter ist gesperrt und erklärt warum. Fremdes Beenden ergibt `nohelper` mit Verweis auf die README. Tests in Task 1 und Task 2.
4. **Nicht unterstützte Distribution** (Debian 12, Ubuntu 22.04): Die Paketverwaltung lehnt die Installation sauber ab, weil Python ≥ 3.12 fehlt. Test: Matrix-Ziel „erwartete Ablehnung“ in Task 6.
5. **Abgelaufener oder bald ablaufender Schlüssel beim Release:** Das Release-Skript bricht vor dem Bauen ab oder warnt. Test mit einem Wegwerfschlüssel kurzer Laufzeit in Task 8.

## Klärungen gegenüber der Spec (Wahl des Planers)

- **K1 – Ort des Helfers:** `/usr/lib/orbitop/killhelper`, eine ausführbare Kopie von `orbitop/killhelper.py`, root:root 0755.
  - `/usr/lib/<paket>/` ist in allen vier Formaten für interne Programme üblich. `/usr/libexec` ist es bei Arch nicht sicher; Task 3 prüft das in der Doku.
  - pkexec startet den Helfer direkt, und sein Shebang `#!/usr/bin/python3 -I` greift. Nur so passt die polkit-Annotation `exec.path` genau auf den Helfer und nicht auf jedes `pkexec python3`.
- **K2 – Programm:** `/usr/share/orbitop/` mit `bin/orbitop` und `orbitop/`. `/usr/bin/orbitop` ist ein Symlink auf `../share/orbitop/bin/orbitop`; die `realpath`-Logik in `bin/orbitop` bleibt unverändert.
- **K3 – Quelle und Schlüssel in eigenen Paketen:**
  - Begründung: Debian Policy 10.7.3 verbietet Paketskripten, Conffiles zu ändern. Eine `.sources`-Datei im Hauptpaket bliebe nach `apt remove` ohne ihren Schlüssel zurück, und `apt update` schlüge fehl (Spec 3, „Pflicht“). Das Muster mit Keyring-Paket beschreibt das Debian-Wiki in UseThirdParty. Nebenbei kommt orbitop selbst so schon geprüft aus der signierten Quelle.
  - **Debian/Ubuntu:** `orbitop-apt-source` mit `.sources`, Schlüssel und apt-Pinning (lintian erlaubt `sources.list.d` nur in Paketen `*-apt-source`; Ruling nach Task 3). Alle drei Dateien sind Conffiles unter `/etc/apt/`: `sources.list.d/orbitop.sources`, `keyrings/orbitop-archive-keyring.pgp`, `preferences.d/orbitop.pref`. Grund: `apt remove orbitop-apt-source` behält Conffiles; läge der Schlüssel unter `/usr/share/keyrings`, bliebe eine Quelle ohne Schlüssel zurück und `apt update` schlüge fehl (Spec 3). Der Schlüsselort `/etc/apt/keyrings` ist nach der globalen Regel des Users erlaubt. Das Pinning (`Pin: origin zappelmann-sketch.github.io`, `Pin-Priority: 100`) folgt Debian-Wiki UseThirdParty: Pakete der Quelle können keine Distributionspakete ersetzen, orbitop selbst wird trotzdem aktualisiert.
  - **Fedora/openSUSE:** `orbitop-release`, je Familie eine Variante, mit `.repo` und Schlüssel.
  - **Erste Installation:** das kleine Paket aus dem Release, dann `apt install orbitop`, `dnf install orbitop` oder `zypper install orbitop`. Die Release-Anhänge haben feste Namen (`orbitop-apt-source.deb`, `orbitop-release-fedora.rpm`, `orbitop-release-opensuse.rpm`), damit die README mit `releases/latest/download/…` auskommt.
  - **Arch:** wie in der Spec. Der Eintrag geschieht von Hand, und das Hauptpaket bringt den Schlüssel für `pacman-key --populate` mit.
- **K4 – Bauweise:**
  - Debian mit debhelper (`dh`, compat 13) aus `packaging/debian/`, binär (`-b`) in `debian:trixie`.
  - RPM mit `packaging/rpm/orbitop.spec` und `packaging/rpm/orbitop-release.spec`, gebaut in `fedora:latest` und `opensuse/tumbleweed`.
  - Arch mit `packaging/arch/PKGBUILD` und `orbitop.install` in `archlinux:latest` als normaler Benutzer.
  - openSUSE `Requires` nutzt die Paketnamen aus `app.PACKAGES` statt der `typelib()`-Capabilities. Beide lösen auf, und ein Test hält die Namen gleich.
- **K5 – Autostart-Vorlage:** `data/autostart.desktop` ist byte-gleich mit der Konstante `orbitop.autostart.TEMPLATE` (Test). Das Paket legt die Datei nach `/usr/share/orbitop/autostart.desktop`.
- **K6 – Update-Test:** Die Matrix baut zusätzlich eine nie veröffentlichte Version mit Suffix, Debian `<rev>+check1`, RPM `Release: <rev>.check1`, Arch `pkgrel=<rev>.1`, und prüft das Update auf sie.
- **K7 – polkit-Texte:** `<message>` ist gleich `polkit.terminate`, `<description>` gleich `polkit.terminate_description` (en als Standard, de als `xml:lang="de"`). Ein Test hält sie gleich. Seit dem Security-Audit von Task 1 endet `polkit.terminate` auf `: $(command_line)`, damit der Passwortdialog PID, Startzeit und Signal zeigt; `<description>` hat keinen Platzhalter.
- **K8 – polkit-Namen:** polkit(8) erlaubt in Action-IDs nur `[A-Z][a-z][0-9].-` und verlangt, dass die Datei nach dem Namensraum heißt. Deshalb ist die Action-ID `io.github.zappelmann-sketch.orbitop.terminate` (Bindestrich statt Unterstrich der App-ID) und die Datei `io.github.zappelmann-sketch.orbitop.policy`.

**Interfaces:**
- Produces in `orbitop/autostart.py` (ohne GTK):
  - `FILE = APP_ID + ".desktop"`
  - `TEMPLATE: str` (byte-gleich `data/autostart.desktop`)
  - `OVERRIDE: str`: `[Desktop Entry]`, `Type=Application`, `Name=orbitop`, `Hidden=true`, je eine Zeile
  - `user_path(env: Mapping[str, str]) -> str`: `$XDG_CONFIG_HOME/autostart/FILE`, wenn absolut, sonst `~/.config/autostart/FILE`
  - `system_paths(env) -> list[str]`: jedes absolute Verzeichnis aus `$XDG_CONFIG_DIRS` (Standard `/etc/xdg`) plus `/autostart/FILE`
  - `state(env, which=shutil.which) -> bool | None`: `None`, wenn `which("orbitop")` nichts findet
  - `set_enabled(on: bool, env, which=shutil.which) -> bool | None`: gibt `state()` danach zurück
- Regeln nach der freedesktop-Spezifikation „Desktop Application Autostart“:
  - Eine Benutzerdatei gleichen Namens geht allen Systemdateien vor.
  - Ein Eintrag ist aus bei `Hidden=true` oder bei `X-GNOME-Autostart-enabled=false` in der Gruppe `[Desktop Entry]`.
- Lesen wie `LayoutFile.load`: `O_NONBLOCK`, nur reguläre Dateien, höchstens 65536 Bytes, sonst gilt der Eintrag als nicht vorhanden.
- `set_enabled`:
  - `True`: Steht schon ein aktiver Systemeintrag da und gibt es keine Benutzerdatei, wird nichts geschrieben. Sonst wird `TEMPLATE` atomar geschrieben (tmp im selben Ordner, `os.replace`).
  - `False`: Gibt es irgendeinen Systemeintrag, wird `OVERRIDE` atomar geschrieben. Sonst wird die Benutzerdatei entfernt; fehlt sie, ist das kein Fehler.
- `data/autostart.desktop` hat den SPDX-Kopf, dazu `Type=Application`, `Name=orbitop`, `Exec=orbitop --hidden`, `TryExec=orbitop`, `Icon=io.github.zappelmann_sketch.orbitop`, `X-GNOME-Autostart-enabled=true` und `NoDisplay=true`.
